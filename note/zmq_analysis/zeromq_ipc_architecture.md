## 4. 技术使用详解

### 4.1 Unix Domain Socket (AF_UNIX)

#### 为什么使用AF_UNIX？

| 特性 | AF_UNIX | TCP Loopback |
|------|---------|--------------|
| 性能 | 更高（内核直接转发） | 需要经过完整TCP协议栈 |
| 安全性 | 只能本机通信 | 可被网络扫描 |
| 凭证传递 | SO_PEERCRED原生支持 | 需要额外认证 |
| 文件系统路径 | 有（可用于权限控制） | 无 |

#### 为什么不用UDP？

| 特性 | AF_UNIX SOCK_STREAM | UDP |
|------|---------------------|-----|
| 可靠性 | 面向连接，保证顺序 | 无连接，可能丢包 |
| 字节流 | 是 | 消息型（但有限制） |
| ZeroMQ需求 | ZMTP基于面向连接设计 | 需要自己实现可靠性 |

### 4.2 SO_PEERCRED 凭证验证

#### 什么是SO_PEERCRED？

```cpp
struct ucred {
    pid_t pid;    // 发送进程的PID
    uid_t uid;    // 发送进程的用户ID
    gid_t gid;    // 发送进程的组ID
};
```

#### 为什么使用它？

```cpp
// ipc_listener_t::filter()
struct ucred cred;
socklen_t size = sizeof(cred);
getsockopt(sock_, SOL_SOCKET, SO_PEERCRED, &cred, &size);

// 内核保证凭证真实性，客户端无法伪造
if (cred.uid != allowed_uid) {
    close(sock_);
    return false;
}
```

**优势：**
- 内核级验证，无法伪造
- 无需额外的握手/认证协议
- 高效简单

### 4.3 accept4() 与 SOCK_CLOEXEC

#### 传统方式的问题

```cpp
// 问题：fork()后，子进程会继承打开的文件描述符
// 如果exec()新程序，fd不会自动关闭，可能泄漏

fd = accept(listen_sock, ...);
// 如果此时fork()，子进程有这个fd
// exec()后，新程序可能意外使用这个fd
```

#### SOCK_CLOEXEC解决方案

```cpp
#if defined(ZMQ_HAVE_SOCK_CLOEXEC) && defined(HAVE_ACCEPT4)
    // accept4() 在接受连接时直接设置CLOEXEC
    // 这样fork()+exec()时，fd自动关闭
    fd_t sock = ::accept4(_s, NULL, NULL, SOCK_CLOEXEC);
#else
    fd_t sock = ::accept(_s, ...);
    // 手动设置CLOEXEC
    fcntl(sock, F_SETFD, FD_CLOEXEC);
#endif
```

**为什么需要？**
- 防止文件描述符泄漏
- 更安全的fd管理
- 减少资源泄漏风险

### 4.4 非阻塞I/O与epoll

#### 为什么非阻塞？

```cpp
// IPC连接可能是异步的
::connect(_s, _addr->resolved.ipc_addr->addr(),
          _addr->resolved.ipc_addr->addrlen());

if (errno == EINPROGRESS) {
    // 连接正在后台进行
    // 注册EPOLLOUT事件，等待连接完成
    _handle = add_fd(_s);
    set_pollout(_handle);
}
```

#### epoll工作流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          epoll 工作流程                                 │
└─────────────────────────────────────────────────────────────────────────┘

  1. 创建epoll实例
     epoll_fd = epoll_create1(EPOLL_CLOEXEC);

  2. 注册监听事件
     epoll_ctl(epoll_fd, EPOLL_CTL_ADD, sockfd, &event);
     // event.events = EPOLLIN | EPOLLOUT | EPOLLERR
     // event.data.fd = sockfd

  3. 等待事件
     while (true) {
         int n = epoll_wait(epoll_fd, events, MAX_EVENTS, timeout);
         for (i = 0; i < n; i++) {
             if (events[i].events & EPOLLIN)  handle_read();
             if (events[i].events & EPOLLOUT) handle_write();
             if (events[i].events & EPOLLERR) handle_error();
         }
     }

  4. 事件触发

     ┌─────────────────────────────────────────────────────────────┐
     │  socket可读 (EPOLLIN)                                       │
     │  ├── 新连接到达 (listen socket) → accept()                  │
     │  └── 数据可读 (connected socket) → read()                   │
     └─────────────────────────────────────────────────────────────┘

     ┌─────────────────────────────────────────────────────────────┐
     │  socket可写 (EPOLLOUT)                                      │
     │  ├── 连接完成 (non-blocking connect) → 完成握手              │
     │  └── 发送缓冲区可写 → write()                                │
     └─────────────────────────────────────────────────────────────┘
```
